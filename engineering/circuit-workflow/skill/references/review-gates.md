# Schematic preservation and acceptance
Use the bundled schematic-humanizer with these project-independent adapter requirements. Owner: circuit-design agent.

1. Identify the authoritative native revision, generator ownership and protected layouts. If current native edits supersede a generator, preserve them; never regenerate from a stale archive. Save hashes, actual before renders and baseline ERC.
2. Complete and log authorized electrical repairs as checkpoint E. Keep intended topology/value/pin changes separate from presentation-only checkpoint P. The integration agent records the transition within existing authorization; this is not a request for a second approval and not certification of unresolved correctness.
3. Use the native EDA exporter to resolve hierarchy and hidden/multi-unit pins. Compare every physical reference/pin partition including isolated pins, explicit NCs, component values/footprints/devices, engineering fields/flags, symbol unit/pin identities and connector roles. Preserve explicit label/global-label/hierarchical-port names and semantics, including aliases omitted by netlist name selection. For genuinely autogenerated names compare pin membership, never ignore explicit names. Prove comparator behavior with deliberate splits/shorts, NC/field changes, multi-unit/hidden/hierarchical cases and harmless autogenerated name changes before relying on it. Upstream compare_connectivity.py omits NC and complete native metadata checks; its pass alone is insufficient.
4. Pilot the hardest functional sheet. Trace local signal, supply, return and bypass/protection paths directly on the render. Excessive label fragments, wires under text, clipped fields, ambiguous crossings and long avoidable loops fail visual review. Inspect every sheet at intended print size and relevant dense crops after annotations. Keep local relationships visibly wired; labels serve actual remote or sheet interfaces. Record reviewed pages, crops, defects and source hashes in the existing project evidence home. If adapting upstream .pcba-workflow location, retain a pointer rather than a second authoritative audit.
5. Keep electrical correctness, visual readability, PCB/manufacturing and physical validation as separate gates. Test bias, loading, startup/reset, switching, signal/mix behavior and grounds against explicit acceptance cases. Generic simulation or ERC cannot prove real transformer/tank behavior or safety. Unknown critical operating limits block the affected gate.
6. Compare final ERC/DRC to baseline. Fix newly introduced applicable violations. Every retained finding needs disposition, evidence, owner and affected gate; old findings are not automatic waivers. Any electrical change after P creates a new E and repeats affected preservation and visual checks. Deliver editable native sources and a readable PDF with overview, sheet navigation and explicit unresolved values.

## Generated netlist intake

1. Record the draft revision and hash. Identify the orderable assembly at each reference, including module versus bare IC, package suffix, socket and mating connector view where applicable. Match the BOM value, symbol and footprint to that assembly.
2. Build a physical pin-to-pad map from the manufacturer drawing. Check supply and return pins, enables, reset polarity, exposed pads, hidden pins and all package units. When using a simulation model, map its argument order separately to the physical terminals.
3. Resolve hierarchical names and aliases with the native exporter. Group endpoints by physical reference and terminal. Flag an endpoint assigned to different electrical nets, required pins omitted from the draft, and explicit no-connect pins that carry a net. Several pads can represent one electrical pin. Preserve documented internal ties and distinct net-tie pads.
4. Compare the exact captured revision with the reviewed draft by pin membership. A regeneration or model retry can change connectivity even when the part and net counts agree. Review each intended difference and rerun the affected checks.
5. Run placement, routing, ERC/DRC and CAM export in the EDA engine that supports the operation. Prefer a supported API or CLI for repeatable operations and use the GUI when needed. Record tool version, active rules, remaining opens and the native reports for the exact revision exported. Check the exported drill and copper against the board.
