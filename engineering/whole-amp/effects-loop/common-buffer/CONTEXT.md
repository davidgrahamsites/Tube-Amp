# Common-buffer headroom decision
Owner: amplifier integration. One job: distinguish normal output-power requirements from overload preservation before selecting the approved common loop buffer.

Inputs: DEC-016, current reverb-600 circuit at f3d258d, effects-loop loaded_feedback_model and generic tube models. Process: compare an unlimited common buffer with explicit 10/12 V output ceilings, using the same preamp, spring-send and output interfaces. Outputs: contract.json, review.md, source-bound decks and measured comparisons under results. No native mutation or device selection. Human check: verify actual transformer/load and listening/bench overload behavior before accepting a reduced voltage envelope.

Done-condition for this pass: completed or explicitly failed bounded comparisons, numerical refinement for the deciding case, reproducible metrics and a justified next architecture action. An ideal clipping model cannot qualify an op amp, pedal protection, noise, rail sequencing or physical safety. Estimated effort: one finite headroom comparison. Existing blocks and all six build requirements remain intact.

CB-002 task: qualify the discrete composite recovery direction before adopting a tube-interface connector or route. Inputs: composite-return.json, archived TI OPAx134 model and declared Microchip-informed generic MOS sensitivities. Owner: integration. Process: standalone DC, closed-loop AC, return-ratio and bounded transient comparisons; preserve active native files. Outputs: composite-review.html and results/composite-summary.json. Done for this pass: reproduce compensation failure/correction and identify current/thermal/model limits. Actual devices, sink, protection, integrated loading and physical validation remain separate gates.

CB-003: operating-point.json selects five CB-002 cases; tools/operating_point.py derives released internal guesses from the valid nominal point, compares original/guided closed/loop fixtures and saves results/op-*. tools/audit_operating_point.py checks raw currents, square-law equations, complex AC crossings and hashes. Done-condition: reproduce invalid points and validate recovered DC/AC without changing CB-002 or native CAD. Human check: never treat initialization as physical startup; keep real devices, full-swing heat/current and integrated loading open.

CB-004: output-heat.json owns the ideal load and thermal assumptions. tools/output_heat.py writes results/output-heat.json. Done-condition: verify load-current and steady heat arithmetic before device selection. Human check: qualify actual integrated capacitance, continuous hot safe operating area, insulated mount and populated heat/screw clearance; a thermal budget alone approves none of these.

CB-005. Integration owns the loaded return-port trial. Join the nominal CB-002 servo and the 600R-1 downstream model through the coupling capacitor. Use the prior open-port probe to check load admittance. Run tools/integrated_load.py with KiCad Python, then tools/audit_integrated_load.py. Read results/integrated-load.json and the CB-005 section of composite-review.html. Done for this trial when all nine cases have a traceable result and each small-signal load agrees with the independent probe. Human check: measure capacitance from the recovery output through its installed harness and verify the selected stage on the bench. Effort: one bounded simulation and load audit.

CB-006. Integration owns the protected return-stage trial after CB-005. Use the hashed Apex Berkeley models, TI macro and CB-005 downstream fixture. Run the three factories listed in apex-return.html. Read signal, stability, fault and thermal results from results/apex-*.json. Human check: verify the supply and independent trip, midpoint startup, external jack isolation, carrier heat path and case temperature before any native layout. This pass delivers a simulation candidate and a placement decision.

CB-007. Amplifier integration owns the 310 V supply and mute trial. Read supply-cutoff.html for the circuit, parts, limits and hold decision. Run its listed factories and tools/audit_supply.py. Inputs are the guarded CB-006 return, existing auxiliary cases and manufacturer limits. Outputs are results/supply-*.json. Human check: establish raw maximum, trip time, signed-rail warning, residual port step and installed package temperatures before three-board placement.

CB-008. Integration owns the receiver guard. Use the CB-007 circuit, PA340 model and the coil, switch and gate data in sudden-loss.html. Run the guard factories in tools with KiCad Python. Compare the fast-fault, detector, gate injection, handover, loaded audio and sustained-load receipts. Human check: capture simultaneous rail, gate and mixer waveforms and compare the populated audio load before placement.

CB-009. Integration owns the winding and revised rail trial. Use winding-rail-fit.html, tools/low_line_rail.py and tools/rail_winding_audio.py. Results are in results/low-line-rail.json and results/rail-winding-audio.json. Compare port, winding, regulator and cutoff waveforms at the same load and temperature before placement.
