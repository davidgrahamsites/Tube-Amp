# Common-buffer headroom decision
Owner: amplifier integration. One job: distinguish normal output-power requirements from overload preservation before selecting the approved common loop buffer.

Inputs: DEC-016, current reverb-600 circuit at f3d258d, effects-loop loaded_feedback_model and generic tube models. Process: compare an unlimited common buffer with explicit 10/12 V output ceilings, using the same preamp, spring-send and output interfaces. Outputs: contract.json, review.md, source-bound decks and measured comparisons under results. No native mutation or device selection. Human check: verify actual transformer/load and listening/bench overload behavior before accepting a reduced voltage envelope.

Done-condition for this pass: completed or explicitly failed bounded comparisons, numerical refinement for the deciding case, reproducible metrics and a justified next architecture action. An ideal clipping model cannot qualify an op amp, pedal protection, noise, rail sequencing or physical safety. Estimated effort: one finite headroom comparison. Existing blocks and all six build requirements remain intact.

CB-002 task: qualify the discrete composite recovery direction before adopting a tube-interface connector or route. Inputs: composite-return.json, archived TI OPAx134 model and declared Microchip-informed generic MOS sensitivities. Owner: integration. Process: standalone DC, closed-loop AC, return-ratio and bounded transient comparisons; preserve active native files. Outputs: composite-review.html and results/composite-summary.json. Done for this pass: reproduce compensation failure/correction and identify current/thermal/model limits. Actual devices, sink, protection, integrated loading and physical validation remain separate gates.

CB-003: operating-point.json selects five CB-002 cases; tools/operating_point.py derives released internal guesses from the valid nominal point, compares original/guided closed/loop fixtures and saves results/op-*. tools/audit_operating_point.py checks raw currents, square-law equations, complex AC crossings and hashes. Done-condition: reproduce invalid points and validate recovered DC/AC without changing CB-002 or native CAD. Human check: never treat initialization as physical startup; keep real devices, full-swing heat/current and integrated loading open.
