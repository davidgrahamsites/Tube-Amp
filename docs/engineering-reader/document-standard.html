Engineering document standard

Authority: user instructions FB-148–151; reinforced by FB-175 on 27 November 2026.

Write for the builder

  • Use aircraft-mechanic English in every new or revised guide section. Use short, direct sentences. State each instruction once.
  • Use one term for one item. Name the part, action, location and condition.
  • Separate an instruction from its reason. Add the reason only when it affects the work.
  • State PASS, FAIL or NOT CHECKED with the evidence. Never use a calculation as proof of physical fit.
  • Use HTML for human-facing reports and read the rendered file before delivery. Keep the file usable offline.
  • Render equations with KaTeX. Keep ordinary instructions as text. Define each symbol and unit beside its first use.
  • Include a vocabulary key for technical terms and abbreviations.

This is a project writing rule, not a claim of compliance with a controlled aviation-language standard.

Check the writing before delivery

  1. State the fault or question first.
  2. Use one action per procedure step. Start with a verb, such as inspect, measure, connect, compare or record.
  3. Name the part and test point. State the required condition, value and unit.
  4. Give the expected result. State the next action if the check fails.
  5. Use the same name for the same part. Define technical terms at first use and in the vocabulary key.
  6. Separate test results from explanations. State what changed and what work remains.
  7. Remove repeated statements and words that add no meaning. Keep conditions, calculations and limits that affect the work.
  8. Read the rendered HTML. Check each instruction against its source evidence.

Example: “Check the simulated op-amp output against its supply rails. If the output exceeds either rail, reject that result and inspect the model setup.” This is a simulation check, not an instruction to probe a powered amplifier.

Record each calculation

  1. State the question and the choice it affects.
  2. List the inputs, units, sources and tolerances.
  3. Separate measured values, model results, nominal ratings and example assumptions.
  4. Show the equation, substitution, result and rounding.
  5. Record failed cases and the check used to verify the arithmetic.
  6. Link the decision, executable calculation and saved result.
  7. State what the result does not establish.

Maintain one current reading copy

The current HTML reports are editable reading copies. Keep prior review versions as dated evidence; do not regenerate an edited HTML file from an older Markdown file. Required routing contracts and machine-readable inputs remain in their tool formats. Migrate an older report when it is used or revised; do not claim the full archive has already changed.

Reader implementation

Equations use local KaTeX 0.16.22 files and fonts. See the KaTeX browser instructions and software license. No network connection is needed to read the reports.
